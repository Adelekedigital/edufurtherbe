§Five principles that shape everything

If you understand only these, you understand the design. Each prevents a specific class of bug that Bubble either caused or couldn't stop.

  • Authorization is profile existence, not a role column. primary_role only picks which dashboard someone lands on. Permissions check whether a mentor_profiles or mentee_goals row exists — which is what makes dual roles free from day one, and why a role column can never silently disagree with reality.
  • user_id is the primary key of every 1:1 extension. Profiles, onboarding, standing, goals — all keyed on user_id, no surrogate. This erases the mentor_profile_id-vs-user_id ambiguity: they're the same value everywhere.
  • Derived data is never stored. Session counts, review counts, availability status, unread counts — all computed at query time. Storing them recreates the exact drift that made the legacy front-search table untrustworthy. (The one exception, a message preview, is trigger-maintained.)
  • Soft delete everywhere, with the partial unique index. WHERE deleted_at IS NULL on unique indexes, or a deleted user permanently blocks their own email from re-registering. Soft delete is never a status, and cascade is banned.
  • Timestamps are enforced, not intended. Every table has created_at + updated_at (timestamptz), auto-triggered, with a CI query that fails the build if one is missing.

§The central move: unbundling User

The legacy User table did five jobs in ~30 columns — identity, profile, OAuth credentials, billing, and onboarding all shared one row, so every profile edit touched the same record as every login. It becomes nine tables.

§The decisions that matter most

35 decisions are logged in full in 01_DECISIONS.md. These are the ones most likely to look arbitrary — or get "re-fixed" — without the reasoning.

D4Keep mentor_id + mentee_id on sessions
Moving them into a participants table felt cleaner, but the double-booking exclusion constraint can't reference a joined table — you'd lose the one guard Bubble never had. And RLS would run a subquery per row on the most-read table. These columns encode a domain invariant: sessions are 1:1 by design.
D5Session status is not derived from attendance
Status exists before anyone attends — a session is pending at creation, cancelled if called off, with no attendance data either way. Attendance informs one transition (confirmed → completed | no_show); it doesn't define the lifecycle.
D6session_events with reason_code AND reason_text
Free text can't answer "what % of mentor cancellations are scheduling conflicts" — which decides whether you build reschedule flows. The enum drives refund policy; the text is for humans. This log also makes "cancelled within 24h of start" answerable for the first time.
D8Credits are a ledger, not a counter
A balance can't survive refunds (no record it happened), concurrency (lost-update race), abuse detection, or accounting once credits are bought. credit_transactions is append-only; balance is a sum.
D12One shared service_offerings vocabulary
Matching failed in Bubble because mentee goals and mentor services were two separate option sets with no mapping. Point both at one lookup and matching becomes a join — before any AI. This table is also the seed for the future tags taxonomy.
D26OTP over magic link
Magic links break twice: Outlook Safe Links prefetches and burns the token, and WhatsApp's in-app browser opens a different session. A 6-digit OTP works everywhere — with hashing, attempt-locking, single-active-code, and per-destination rate limits, because 6 digits is brute-forceable.
D33audit_log separate from session_events
One is domain state queried by features and needs a rigid schema; the other is the generic catch-all with jsonb before/after snapshots. Both append-only. Don't collapse them.

§What changed during design

Six decisions were revised mid-process. Recording both the original and why it was wrong is what stops someone re-introducing the earlier version.

D7Credit periods → credit lotsrevised
The lot model handles free and paid credits with different lifecycles in one structure.
Was: monthly-reset periods — which assumed all credits are free. Paid credits must never expire (that's a chargeback), so a single balance couldn't represent both.
D13Scholarship data moved to user levelrevised
A relationship field (awarded / applied / advised) lets one table serve both a mentee's credential and a mentor's capability.
Was: filed under mentor services — conflating "I won Chevening" (a fact about a person) with "I advise on Chevening" (a mentor offering).
D15Institutions: registry, not mirrorrevised
Populate on demand from Hipolabs autocomplete — ~200–400 rows of what's actually referenced, not a 9,000-row mirror. But still a table, so country derives once and FK integrity holds.
Was: seed the whole ROR catalogue. Storing only the string would've returned you to 940 rows of free text.
D20listing_status binary, availability derivedrevised
One field plus an internal reason. Profile-page access is a viewer-side rule, not a column.
Was: two booleans — but is_available was derivable (drift risk), and "paused but visible" conflated searchability with access.
D22Notifications: hybrid typed FK + jsonbrevised
Typed FK only for the three entities needing cascade or list-join (session, review, conversation); everything else in a context jsonb read by templates, never logic.
Was: a typed column per type — a migration every time a notification kind is added.
D32Multi-tenancy deferred, not pre-builtrevised
Retrofit is a weekend on this schema. Only guard against globally-unique human-readable keys meanwhile.
Was: "add organization_id now, it's cheap." It isn't free — every query, index, and RLS policy carries it indefinitely for a maybe.

§Where the risk actually is

Most of the ~6,800 rows are low-risk. Three things aren't, and each has a specific check to run before cutover.

M3 · Availability & DST

Legacy stored pre-formatted local time strings. Getting the timezone conversion wrong produces silently-wrong slots, and DST breaks it twice a year.

Check: reconstruct a known mentor's next 7 days across a DST boundary and compare against what Bubble shows. Test 5 mentors in 3+ timezones.

M4 · The booking/tracker merge

1,073 bookings vs 935 trackers. The gap and any multi-tracker bookings (reschedules) determine the merge strategy.

Check: run the reconciliation query before writing the transform — confirm the ~138-row gap is cancellations, and find any booking with multiple trackers.

M4 · The exclusion constraint

Legacy data almost certainly contains double-bookings Bubble allowed. The new constraint will reject overlapping active sessions.

Check: find overlaps in staging first. Completed sessions pass (the constraint only covers pending/confirmed); resolve genuinely conflicting active ones by hand.

Files · Bubble S3 dependency

Every avatar and banner URL points at Bubble — a live dependency on the platform you're leaving.

Check: before cutover, every image URL query must return zero rows matching %bubble%.

§Deliberately not built this phase

Each was considered and rejected for a reason — at 1,200 users most performance infrastructure is premature.

  • Redis / caching — indexes + TanStack Query cover it; adding it now buys an invalidation bug, not speed
  • Typesense / Meilisearch — Postgres FTS + trigram is enough until ~10k mentors
  • Third-party chat — ~$400+/mo for 13 conversations; Supabase Realtime is free and present
  • Novu — 681 notifications don't justify it; two tables + a dispatcher suffice
  • Multi-tenancy — retrofit is a weekend; just avoid globally-unique human-readable keys
  • Capacitor — ship the PWA, measure iOS install rate first
  • pgvector matching — 44 mentors is too small for embeddings to beat filters + rating
  • tags taxonomy — deferred; service_offerings is the seed

Do build now, though

  • Cursor pagination on every list endpoint — retrofitting is a breaking API change
  • Idempotency keys on booking — a retried POST double-books and double-charges; mandatory before payments
  • The reporting schema — makes dashboards survive refactors and makes Metabase's natural-language querying actually work
  • message_type + payload columns — two columns now make slash-command action cards a frontend project later, not a migration

§Deferred work & its triggers

Every deferred item has a defined escape hatch — that's what makes deferring safe. None require a redesign later.

Tags / AI matching taxonomy→ when AI matching begins
service_offerings already gives both sides a shared vocabulary; basic matching is a join today. Migration to tags is one pass, no redesign.
pgvector embeddings→ ~200+ mentors
Filter-first-rank-second means structured fields are needed regardless. Build match_impressions / match_outcomes early — that's training signal you can't create retroactively.
Payments→ business decision
The lot model already accommodates it: unit_cost_cents and currency sit at zero, paid credits never expire. Consider Paystack / Flutterwave for Nigeria over Stripe.
Award verification→ if claims drive bookings
Self-reported this phase; columns exist and default to unverified. Enabling verify-on-request is a feature flag.
Slash-command action cards→ product decision
Schema is ready. Card state derives from the referenced session, cards expire, and actions reuse the normal booking endpoint.
Composio replacement (Nango / direct)→ if token custody becomes a requirement
calendar_connections stores a reference, not tokens — switching touches one table and one module.

§Open decisions

Two remain. Neither blocks starting M0 or M1.

1
What counts as a qualifying invite?
Recommend invitee-completes-onboarding. Email-verified alone is farmable with disposable addresses; session-completed delays the referrer's reward and weakens the loop. Blocks B1.
2
Payments architecture
Separate discussion. The lot model keeps it additive, so it doesn't gate the migration. Blocks nothing now.
Already resolvedDual roles (profile-existence authorization makes it free), verification policy (self-reported this phase), institutions (lazy registry), and scholarship modelling (user-level) were all open earlier and are now settled.

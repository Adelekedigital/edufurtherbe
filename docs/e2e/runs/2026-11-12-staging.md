## What changed in the scenarios

- Every `TODO(frontend)` UI step is written; UI steps stop before the write their API step makes, except MENTOR-001's Submit.
- Fixed expectations: the session-type PATCH answers `{updated}`; BOOK-001 sent a placeholder `answers`; signed out, analytics answers 401 with the flag on; CANCEL-002's slot window is a week wide; ACQ-001 uses an account that never opened the app.
- MENTOR-001's `submit` reads the result, since the UI submits.
- `consent` on a UI step: the runner otherwise hides the consent banner, because answering it writes consent to the account.
- Agent sign-in: the session script's link returns the session in the URL hash, which the app does not accept (PKCE only, on purpose). The runner sets the session cookie from it; see the frontend's `docs/e2e/README.md`.
